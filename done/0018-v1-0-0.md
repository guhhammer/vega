# 0018 — 1.0.0

`chore: release 1.0.0`

## What landed

The version in `Cargo.toml`, `app/package.json`, `app/src-tauri/tauri.conf.json`
and both lockfiles, a `[1.0.0]` changelog section, and the release documentation
updated to match.

## What this release is

Packaging. The protocol, the crypto and the transport code are unchanged from
0.1.0. What changed is that there is now something to download on three
platforms, checksums to verify it against, and instructions for installing it.

## What the number does not mean

It does not mean the cryptography has been reviewed, and it does not mean the
wire format is frozen. Neither is true.

This is worth recording because the repository previously said 1.0 *should* mean
both of those things, and shipping a 1.0 that means neither is a decision, not
an oversight. A version number is read as a maturity claim whether or not it is
offered as one, and it is now the only signal in the repository pointing that
way — SECURITY.md, the threat model, the README and the changelog all say
plainly that nothing here has been audited.

The honest reading is that the version tracks the application and not the
protocol, and `releasing.md` now says so where it previously said the opposite.
Leaving that section as it was would have left the repository contradicting its
own tag, which is worse than either position taken on its own.

## The wire format caveat moved, not removed

The changelog header previously carried a "pre-1.0" caveat about the wire format
being unstable. Dropping it on a 1.0 would imply the guarantee it was there to
deny, so it is now stated without reference to the version: the format is not
stable, two builds may not talk to each other, and a change to the encoding
needs a major bump and a migration rather than a note.

## What would earn the words

An external review of `vega-core`, and a format settled enough that a build from
a year earlier still talks to a current one. Until then the number describes the
packaging and the documents describe the risk.
